## Every Stage has 5 questions

- Why? what are we trying to prove?
- What? what should we do?
- How? How can we test it
- Evidence? What proves progress?
- Next? What do we need to learn next?

1. SRL 0 : Competencies Based Target Market Analysis
    - Focus: Capability, Market Opportunity, Purpose
    - Tools: Competerncy & Resource Mapping, TAM, SAM, SOM, Market Opportunity, Mindset & Purpose
    - Evidence: Team Capability Map, Resource Management, TAM/SAM/SOM Analysis

    - Ketahui dulu dari prespektif Investor itu dia mau invest ke orang yang bagaimana? Kompeten? Jujur.
    - Pastikan lagi di Pitchdesk ada muncul teamnya (kompetensinya) dan kapabilitasnya apa. Misal kita punya marketing tapi tidak kompeten di marketing, solusinya bisa imporove knowledge (belajar marketing)

2. SRL 1 : Problem Validation
    - Focus : understand the customer before selling the solution
    - Evidence : 1. Market opportunity navigator 2. Problem validation 3. Purpose Statement 4. Customer & user persona
    - What to do: 1. Customer profilling 2. Interviews 3. Surveys 4. Problem Discovery 5. Customer Development 6. Value Propostion

    **Ask Better Opportunity:**

    `Would you use our app?`

    `How do you solve this problem today?`

    `What have you already tried?`

## Observe Behavior. Don't collect compliments

    - Problem Validation: Bukan menjadikan "mau gak pakai aplikasi saya?", tapi "dari masalah ini, sudah pakai cara apa saja?". Kita pastikan customer itu maunya apa? dan validasi (bikin value porpotition), customer painfull dimana, purpose validation (mau ngapain), customer dan user personalnya harus ada. Intinya profiling customer dulu (Produknya apa? Targetnya siapa? Bikin Personanya? Cara Reach Mereka gimana (bisa lewat hobi dan komunitas)). Pastikan lagi bahwa problem mereka belum teratasi, kalaupun sudah teratasi jika masih ada kata "Tapi", berati masih ada celah dan masih bisa masuk. Bisa jadi ini kita sudah capai MVP, tapi check lagi apa sudah oke belum nih? pastikan benar benar, mau pakai, dan willing to pay.
    - Note: Cari seberapa painfullnya customer

3. SRL 2: Solution Concept Validation
   does our proposed solution address the validated problem?
    - From problem to solution
    - Test Before Building: 1. Pitch experiment 2. Conclerge experiment 3. Wizard of Oz 4. Prototype 5. UVP Testing 6. Solution Feedback
    - Evidence: 1. Pitch Result 2. Experiment records 3. Prototype 4. UVP 5. Custom Feedback 6. Solution Iteration

    - setelah ketemu problem dan solusinya, kita validasi lagi apa benar benar terpenuhi problemnya. Pitching dulu ke end user (bisa pakai prototype), user biar nyoba dulu. Intinya konsep kita itu tervalidasi dengan cara yang paling sederhana (kalau produk jadi ya produknya, kalau bukan produk jadi ya disimulasikan, atau di presentasikan)

    - Contoh:

    - Poitnya : Sebenarnya Value yang dibutuhkan customer itu seperti apa?

    - UVP : dari masalah ini, itu ada solusi apa? jika sudah ada competitor kita brenchmarking dulu competitornya. Sehingga ketika sudah ditahap solution, harapanya kita sudah tau nih fit solutionnya apa (targetnya mau masuk dimana). brenchmarking ada yang direct (yang satu model) dan indirect.

    - Note: Dont build too early. Test manually first.

4. SRL 3: MVP Readiness, Can we implement the solution as an MVP and generate real learning from users?
    - MVP should: 1. Solve a meaningfull problem, 2. Generate measureable data
    - Evidence: 1. Functional MVP 2. Early Adopter Data 3. User Testing 4. Feedback mechanism 5. Product Backlog 6. Iteration History 7. Version Change 8. MVP Validation Results

    - Fungsi MVP: Validasi ide, solve the problem, Mengenalkan produk ke user dengan fitur dasar. Intinya ngambil data customer untuk digunakan decision making (pivot). Kapan sih pivot? jawabanya "Datanya yang kita punya bilang apa". Minimal 1 iterasi. Version change dari feedback dan backlog.

    Note : MVP not same Findal Product, selesaikan dulu core problem. Bisa jadi end user itu sudah punya masalah banyak, tapi untuk masalah yang non core itu mereka sudah ada existing solutionnya. Bukan smaller version -> Fitur yang mendasar (core)
    - Iteration:

    - The Iteration Loop: Semua berawal dari hypotesis, hypotesis harus dieksperimenkan, lalu kita akan dapat data, learning, adapat, retest

    - Note : Kalau produknya software, iteration ini dihitung dari backlog. Targetnya adalah disetiap iterasi, untuk mendapat feedback dari user. Agar semakin yakin dan valid.

5. SRL 4: Product Validation, SRL 3: Can people use it?, SRL 4. Do they want to keep using it?
    - Note: kalau dari stage 3 itu user mau pakai gak? kalau distage ini fokusnya adalah mau nggak berketerusan untuk pakai product ini. Evaluasi kalau ada user yang berhenti, berati thre is something wrong. Tujuannya adalah tau kapan kita akan balik lagi ke stage stage awal untuk nambal.

    - Focus: 1. Early Adopters 2. Repeat Usage 3. Retention 4. Feedback 5. NPS 6. LTV where applicable
    - Evidence: 1. Repeat Usage 2. Retention Data 3. Early adopter records 4. Partner Evidence 5. Customer Feedback

    - Customer Behavior is Stronger than Customer Opinion

    - Di Product (customize) -> Beli putus, dia akan pakai terus, it means lifetime valuenya akan pakai terus, sampai gabisa dipakai lagi. Makanay kita perlu tau iteration productnya itu berapa lama.
    - Maksud dari iterasi disini adalah lifecyclenya berapa lama (misal jika langganan GPT itu 1 bulan, maka bisa dikatakan lifecyclenya 1 bulan). Iterasi itu bukan durasi pengerjaanya tapi penggunaan produk oleh end user. Utamakan produknya iterasinya cepet.

    - Tanda puncak keberhasilan Evidence Ladder SRL 4: "I reffered someone"

6. SRL 5: Bussiness model validation, Pointnya Revenue Streamnya kelihatan (Racik Bisnis Model)

    - Point utama Bisnis Model, dan revenue steam, can we make money?
